## Docs Site That Shows the Product — Requirements

> Refined. Run /spec docs-site-restyle next.

> Restyle the Jekyll site on GitHub Pages in the brand: a Night landing page that leads with the hero recording and the quickstart, Paper docs pages with a grouped sidebar, an on-this-page list and client-side search, consistent reported / estimated / unknown labels, code examples marked "tested in CI" only when CI runs them, and no horizontal overflow at 390px. A slice of the public release gate G10 and the design direction D-97. Normative source: mythhelm-synthesis/MYTHHELM_Master_Spec_v2.md, version 2.0 (via docs/spec/README.md); § numbers, I-IDs, G-IDs and AT-IDs refer to it.

## Context

- **Backlog card**: MH-33

The published site (`docs/`, built by `.github/workflows/docs.yml` with `actions/jekyll-build-pages`) does not show the product. Its custom layout `docs/_layouts/default.html` replaces the minima theme layout, links only minima's `assets/main.css` and none of the brand assets, so pages render nearly unstyled: a flat seven-entry bulleted nav above every page (`docs/_data/navigation.yml`), unbounded line length and demo GIFs at native size. The User guide measures 516px wide in a 390px viewport with 13 `pre`, `table` or `img` elements overflowing. There is no search and no on-page table of contents.

Terms. A **published page** is every HTML page the Jekyll build emits from a Markdown source under `docs/`. It is not limited to sources with front matter: the live site also serves the front-matter-less sources as HTML pages titled from their first heading (HTTP 200 on `/mythhelm/automation.html`, `/mythhelm/harness/charter.html`, `/mythhelm/spec/master-spec.html` and `/mythhelm/decisions/0007-stop-and-recovery.html`, 2026-10-12), and `docs/limitations.md` links to a rendered decision page (`grep -n "decisions/0018" docs/limitations.md`). The Markdown sources number 39 (`find docs -name '*.md' | wc -l`): four with front matter (`docs/index.md`, `user-guide.md`, `contributing.md`, `limitations.md`), the four root-guide mirrors that the build job gives front matter transiently, and the rest rendered with the default layout. Which of them the build emits is read from the built `_site`, never from a count in this spec. The phrase "the published pages" below means that set. **The state labels** are the data classes MYTHHELM labels: `reported`, `estimated` and `unknown` appear on the site; `observed` has no site label today, and `user-declared` is covered by AC-5.4.

The decisions the design direction records (D-97 in `product/decisions.md`): a Night landing page and Paper docs pages; stay on Jekyll and GitHub Pages and add a client-side search index. The remaining specifics come from the maintainer's design summary and are not recorded in the repository (see OQ-11): the hex values for Night (`#090f1a`, in the brand README) and Paper (`#f6f4ee`, in no repository file), brand tokens from `docs/assets/brand/README.md`, Star (`#4ddae9` dark, `#00829d` light) as the only accent, amber (`#f0c27b` dark, `#8a5a00` light) meaning "needs you" and nothing else, the wordmark in Archivo Expanded ExtraBold and JetBrains Mono as the secondary face. The design has a 1280px landing page (nav with the M crest, search and a "pre-alpha" pill; the headline; the `go run ./cmd/mythhelm demo` quickstart; the hero recording with chapter controls; four "why not just tmux" cells each paired with a peer-user need; a works / in progress / not yet panel; a footer), the same order at 390px, and a Paper docs page (sidebar grouped Start / Use / Understand / Reference, on-this-page list, consistent state labels, "tested in CI" code blocks, a "declared, not verified" note style). The user research (`.claude/data/design-review/research.md`, git-ignored) says docs readers want the quickstart first, examples that run, search, and no gaps off the happy path; it also warns that the "command deck" reads as another multiplexer, so the page leads with attention, recovery, readable evidence and honest budget. Laws of UX to honour: Jakob (familiar docs layout), common region (nav grouped by intent), Hick (few top-level choices), aesthetic-usability, progressive disclosure; tap targets of at least 44px.

The central risk is the card's own (risk 2): the site is the first thing a person reads, and v2 G10 requires published limitations for every advertised capability (I14). Today the Claude Code adapter and the scripted adapter ship, Codex is explicitly not a supported adapter (`docs/limitations.md`, `grep -n "^### Codex" docs/limitations.md`), `subscription-only` blocks every run (`docs/limitations.md`, `grep -n "subscription-only" docs/limitations.md`; `README.md`), and the TUI's attention-first default view is MH-23, not shipped. ### Objectives

- **O1**: A person landing on the site sees what MYTHHELM does and the quickstart without scrolling: at 1280x800 and 390x844 the top edge of the quickstart block is inside the first viewport (D-97, G10).
- **O2**: A reader of any docs page finds their way by grouped navigation, an on-this-page list and search, on a phone as well as a desktop (D-97).
- **O3**: Nothing on the site claims more than ships: the status panel, the state labels and the "tested in CI" marker are each backed by a source a check reads (I09, I14, G10).
- **O4**: The site is on brand and legible in both palettes without a build system beyond Jekyll (D-97).

## Functional Requirements

Acceptance criteria use EARS. Tags in brackets name the invariants, gates and sections each one serves.

### FR-1 — Brand layout and tokens (D-97, G10)

- **AC-1.1** [D-97] When a published page is built, the site shall serve a layout that carries the brand tokens (Night, Frost, Ink, Star dark and light, Mist, Paper, the two amber values) as CSS custom properties and the M crest mark in the header: the landing page on the Night surface and every other page on the Paper surface. The layout keeps the name `default` (`layout: default` in the four pages' front matter and in the mirror injection step of the build job; front-matter-less pages receive a layout through the Pages defaults, which the design confirms with a build, so a `defaults:` entry in `docs/_config.yml` assigns the docs layout to every page explicitly, and a check on the built site fails when a published page lacks the layout's marker, with a fixture page that lacks it) or the same change updates those five places; `theme: minima` and its `assets/main.css` are either removed or no longer determine any visible style, and the choice is recorded in the design.
- **AC-1.2** [D-97] Every colour literal in the site's stylesheet (hex, `rgb()`, `hsl()` or named colour) shall be the value of a custom property whose name and hex appear in the brand README's colour table (`docs/assets/brand/README.md`), and a check shall fail when a literal is outside the table or a table row differs from the stylesheet; the check ships with a stylesheet fixture holding an unlisted hex and a fixture whose table row differs from the stylesheet's property, each of which it must reject. `transparent` and `currentColor` are allowed; derived colours (alpha channels, `color-mix()`, `opacity` used to tint text) are not, so muted text on Paper uses Ink and a new token is a brand change decided under OQ-11.
- **AC-1.3** [D-97] Star shall be the only accent colour on both surfaces, and the site has no "needs you" element, so no rule outside the token declarations shall reference an amber token unless OQ-6 decides the "declared, not verified" note uses them; the check fails on any such `var()` reference and ships with a fixture rule that does so, which it must reject. The landing page's attention cell uses no amber chip.
- **AC-1.4** [D-97] The code and label face shall be JetBrains Mono with a system monospace fallback, the body face a readable system or secondary stack, and the wordmark Archivo Expanded ExtraBold or the brand lockup asset, per OQ-3.
- **AC-1.5** [I13 (v2 §2)] If a built page references a font, script, stylesheet or image from an origin other than the site's own, then a check shall fail the build; links the reader follows (GitHub, issues) are not loaded resources and do not count; the check ships with a fixture page that loads a script from another origin, which it must reject.

### FR-2 — Night landing page with the hero recording (D-97, G10)

- **AC-2.1** [D-97] The landing page shall show, in this order: the nav (crest mark, search, "pre-alpha" pill), the headline (per OQ-1), the `go run ./cmd/mythhelm demo` quickstart, the hero recording, four "why not just tmux" cells each paired with the peer-user need it answers, the works / in progress / not yet panel, and the footer; at 1280px and at 390px the order is the same and the top edge of the quickstart block lies within the first 800px and 844px of height respectively.
- **AC-2.2** [D-97] The hero recording shall be the real recording of `docs/demos/hero.tape`, shall carry chapter controls (title, run, kill, recover, review) that seek to the matching moment, shall not autoplay, and shall have a poster; the format is decided by OQ-2.
- **AC-2.3** [I14 (v2 §2)] The works / in progress / not yet panel shall be generated from a data file (`docs/_data/status.yml`) whose items each name a section of `docs/limitations.md` and quote a phrase from it, and a check shall fail when a quoted phrase is absent from the named section's text (anchored to the region under that heading, not the whole file); the check ships with a fixture whose quoted phrase was removed from its section, which it must reject. The "in progress" column's source is decided by OQ-9.
- **AC-2.4** [I14 (v2 §2), G10 (v2 §18.3)] Each "why not just tmux" cell shall name the capability it rests on and link its evidence (a `docs/limitations.md` section, a user-guide section or a qualifying test named in `docs/demos/manifest.json`), and a cell whose capability is not shipped shall carry the label the panel gives that capability under OQ-9 ("in progress" or "not yet"), never be stated as working; the cell texts are decided by OQ-1.
- **AC-2.5** [G10 (v2 §18.3)] No existing assertion in `.github/workflows/docs.yml` (mirror freshness, manifest revisions, transcript freshness, qualifiers, "Assert mirrors rendered") shall be removed or weakened, and every published page shall show links to the licence, security policy, changelog, governance, limitations and contributing pages in a place visible without opening a control (the footer); `docs/_data/navigation.yml` adds the governance page, which is today reachable only through `docs/contributing.md`.
- **AC-2.6** [D-97] The quickstart block on the landing page and in the user guide shall be the same command text, copyable, with the note that the first build needs the Go module cache populated (`README.md:46`).

### FR-3 — Paper docs layout (D-97)

- **AC-3.1** [D-97] A docs page shall show a sidebar whose entries are grouped under Start, Use, Understand and Reference, with at most four top-level groups and the current page marked; the group of every page in `docs/_data/navigation.yml` is data in that file, not hard-coded in the layout.
- **AC-3.2** [D-97] A published page with two or more second-level headings shall show an on-this-page list of those headings, generated at build time, each linking to its anchor; a page with fewer than two second-level headings shows none.
- **AC-3.3** [D-97] The prose column shall be bounded to at most 80 characters per line, and a long `pre` or `table` shall scroll inside its own container, never widen the page.
- **AC-3.4** [D-97] Where the viewport is narrower than the sidebar's breakpoint, the sidebar shall collapse behind a labelled control that works with keyboard and touch and, without JavaScript, shall remain reachable as a plain link list.
- **AC-3.5** [D-97] The four mirrored root-guide pages shall render in the same layout with the same sidebar and on-this-page list.

### FR-4 — Client-side search (D-97)

- **AC-4.1** [D-97] The build shall emit a static search index of every published page (title, group, headings with anchors, body text), generated by Jekyll with no runtime service, and fetched only when the visitor first uses search, so the index never counts toward the landing page's weight (NFR-3); the design bounds the index's size, for example by excluding the body text of the largest pages (`docs/spec/master-spec.md` alone is 217,947 bytes, `wc -c`).
- **AC-4.2** [D-97] When a visitor types a query that matches a heading or body text, the search control shall list matching pages and sections ranked with title and heading matches first, each linking to its anchor; a query matching nothing shall say so.
- **AC-4.3** [D-97] The search control shall be reachable by keyboard (a documented shortcut and Tab), announce result counts to assistive technology, and work offline once the page and index are loaded.
- **AC-4.4** [D-97] While JavaScript is unavailable, the page shall hide the search control rather than show an inert one, and every published page shall remain readable and navigable.
- **AC-4.5** [D-97] A check shall fail when the built index lacks a published page, and shall be shown to pass on the built site and fail on a copy of it with one page removed from the index.

### FR-5 — State labels (I09)

- **AC-5.1** [I09 (v2 §2)] The site shall define one markup convention for the three data states `reported`, `estimated` and `unknown`, documented for authors, rendered with a consistent style on both surfaces: `unknown` with a dotted underline, and each state distinguishable without colour. User-declared data is covered by AC-5.4.
- **AC-5.2** [I09 (v2 §2)] Where the user guide's prose names a state as a data label MYTHHELM prints or records (the label definitions in its budget section, `grep -n "for exact\|estimated" docs/user-guide.md`, and the sentences saying a field is `unknown` rather than zero), the prose shall use the convention: a code span holding only a state word that names a data label MYTHHELM records becomes the markup (``grep -n '`\(reported\|estimated\|unknown\)`' docs/user-guide.md`` lists the candidates; the design names which are in scope). Ordinary English uses of the words ("unknown keys", "the reset is unknown"), output lines such as `remaining: unknown`, field paths and the values of other enums stay verbatim. If the markup is given an empty or unrecognised state, then the built page shall render `unknown`, never a blank and never zero; the check of AC-5.3 renders a fixture page doing so.
- **AC-5.3** [I09 (v2 §2)] A check shall fail when the state class wraps text other than one of the three state words (it ships with a fixture page that does so, which it must reject), and the three states shall each appear in at least one built page so the check cannot pass on zero matches.
- **AC-5.4** [I14 (v2 §2)] A "declared, not verified" note style shall exist for statements MYTHHELM does not verify, and the user guide's declared-billing and entitlement statements shall use it (a markup change; the text is not rewritten).

### FR-6 — Code examples marked and tested in CI (G10, I14)

- **AC-6.1** [I14 (v2 §2)] A fenced code block shall carry a "tested in CI" marker only when an entry in a checked-in examples list names it and the command that CI runs for it; a block with no entry shall render without the marker. The existing `<!-- Output of: ... -->` provenance comments in `docs/user-guide.md` (`grep -c "Output of" docs/user-guide.md`) stay and do not earn the marker by themselves.
- **AC-6.2** [I14 (v2 §2)] A CI job shall run every listed example command as written and fail when one exits non-zero (the check ships with a fixture entry whose command exits non-zero) or when an entry names a block that no published page contains (the check ships with a fixture entry naming a missing block, which it must reject); the quickstart `go run ./cmd/mythhelm demo` shall be the first listed example, run non-interactively and offline (after `go mod download`, with `GOPROXY=off`).
- **AC-6.3** [I14 (v2 §2)] If a marked block's text changes without its entry, or an entry's command changes without its block, then the check shall fail, and it ships with a fixture for each of the two cases.
- **AC-6.4** [I14 (v2 §2)] A block that shows command output shall be marked only when the examples job diffs the command's normalised output against the block and fails on a difference (the check ships with an output block that differs from the normalised output, which it must reject); otherwise output blocks stay unmarked.
- **AC-6.5** [AT-46 (v2 §18.2)] The examples job shall need no agent credentials and no paid service and shall run on pull requests from forks.

### FR-7 — Responsive, accessible layout (D-97)

- **AC-7.1** [D-97] At viewport widths 390px and 1280px, every published page shall have a document scroll width no greater than the viewport width, and a check shall assert this against the built site for every published page of the built site, including the longest (`user-guide.html`); the check ships with a fixture page containing a `pre` wider than the viewport outside its scroll container, which it must reject.
- **AC-7.2** [D-97] Interactive targets (nav links, the search control, the sidebar toggle, copy buttons, recording chapter buttons) shall be at least 44px by 44px at 390px.
- **AC-7.3** [D-97] Body text and links on both surfaces shall meet 4.5:1 contrast and large text and UI parts 3:1, with the Star-on-Paper treatment decided by OQ-4, and a check shall assert the token pairs the stylesheet uses and reject a fixture pair below the threshold.
- **AC-7.4** [D-97] Demo images and their captions shall fit the column with the caption below the image, and every recording shall carry a text alternative that names what it shows and that it is scripted. The user guide's three autoplaying GIFs (`docs/user-guide.md:39-46`) shall be served as static posters with the recording started on request, or replaced by the OQ-2 player.
- **AC-7.5** [D-97] Where the visitor prefers reduced motion, no recording or element shall animate unprompted, and a static poster stands in for every GIF; the landing page stays Night and the docs pages stay Paper whatever the visitor's colour-scheme preference.

## Non-Functional Requirements

- **NFR-1** [I13 (v2 §2)] The site makes no request to a third-party origin and ships no analytics (checked by AC-1.5).
- **NFR-2** [N1] The "Build docs site" job's duration and the built site's total size are recorded in the pull request before and after, so the card's "revisit if build speed hurts" has a number.
- **NFR-3** [G10 (v2 §18.3)] The landing page's transferred weight excluding the hero recording is at most 500 KB, and the hero recording is not fetched before the visitor starts it (`preload="none"` with a poster); today the page loads two GIFs of 1.67 MB and 1.24 MB (`ls -l docs/demos/*.gif`).
- **NFR-4** [D-97] Site content is generated only by `actions/jekyll-build-pages` and the existing mirror front-matter injection; steps that check sources or the built `_site` are allowed. Check fixtures are built by a separate check build that reuses the layouts and is never deployed, indexed or linked from the site. Jekyll plugins stay within the GitHub Pages allow-list, and any new GitHub Action is pinned to a full SHA (`.claude/rules/github-workflows.md`).
- **NFR-5** [D-97] The built search index is at most 300 KB uncompressed (a conservative default the maintainer may change), and a build check fails above it and ships with an oversized fixture index; the design chooses what to exclude (AC-4.1).

## Open Questions

Each has a conservative default the design may use until the maintainer decides.

- **OQ-1 — Headline and the four "why not tmux" cells versus what ships.** The headline "Run the agents you already trust. Know what they actually did." and an attention-queue cell claim more than the shipped adapters and TUI do (Codex unsupported, MH-23 not shipped). The cell texts and their peer-user needs exist only in the design file. Blocks AC-2.1 and AC-2.4 copy. Options: keep the headline, keep the pill in the nav (AC-2.1's order), put at most a one-line link to the status panel under the headline, and use the four cells attention (approvals, MH-23), recovery (session recovery), readable evidence (readable verification) and honest budget (quota gauge), the first carrying the label OQ-9 gives it, "not yet" under OQ-9's default (default); reword the headline to what ships and widen it when more adapters qualify; or hold the landing launch until MH-23 ships. Maintainer decision (owns a public claim).
- **OQ-2 — Hero recording format with chapter controls.** The hero is a GIF; a GIF has no seek or chapters. Blocks AC-2.2. Options: render `hero.webm` (and MP4 fallback) from the same tape with VHS and drive an HTML5 `<video>` with chapter buttons whose offsets live in `docs/demos/manifest.json` (default; adds an output and a check that offsets are ordered and inside the duration); an asciinema player (new recording tool and a third-party script; replaces the pipeline); or keep the GIF and make chapters links into the transcript (no seeking; would amend AC-2.2 and NFR-3, which need pause, a poster and `preload`). It also decides whether the transcript-freshness job covers the video.
- **OQ-3 — Fonts.** Archivo Expanded ExtraBold and JetBrains Mono are OFL and not in the repository (`docs/assets/brand/README.md`). Blocks AC-1.4 and AC-1.5. - **OQ-4 — Star on Paper contrast.** Star light `#00829d` on Paper `#f6f4ee` is 4.08:1, below 4.5:1 for body-size text. Blocks AC-7.3.
