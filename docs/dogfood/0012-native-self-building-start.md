# Native product-task trial rejected — 2026-11-02

**MYTHHELM launched actual native work on a product task. The first attempt in
this November 2 trial was independently rejected. The full product is unfinished,
and at least 20×
faster full-product delivery is not demonstrated.**

This is a fixed **2026-11-02 12:51:55 UTC snapshot**, based on main `6f4323a`.
The [09:03 blockers report](0011-responsive-layout-blockers.html) remains a
historical snapshot; later repairs and merges do not rewrite its failures.
Routine delivery observations are not a controlled comparison.

pilot](0003-measured-self-hosting.html) recorded an accepted self-hosted safety-test
change and one completed matched development pair. Direct native-reported
execution was 58.182 seconds versus 87.093 seconds through MYTHHELM. Coordinator
waiting confounded the acceptance endpoint; the one independent repository/task-family
component established no advantage. That report recorded an open delayed-defect
window; a later follow-up result is unknown here.

## Actual native execution, rejected delivery

MYTHHELM admitted and owned a native Claude Code attempt on a
supervisor-attachment-control product task. This was actual self-use, separate
from direct coordinator authoring. The native process reported success and
exited zero. Two attempted edits were denied; the candidate remained unchanged.
Three default Go checks passed over that unchanged source. The run reached
`ready_for_review`, which is a review stage, not acceptance. Independent review
rejected the result. No product-task completion follows from those checks.

The checks had already completed before the coordinator's stop request could
prevent them. That ordering is retained rather than describing the request as
having stopped verification. Owned native and worker processes were reconciled
as gone, with no unresolved descendants. Before/after official authentication
metadata matched, and the existing native login was preserved. The coordinator
did not extract or copy native subscription secrets; this does not audit or
exclude the native client's legitimate use of its own authentication. These
observations do not establish general lifecycle or
subscription-only qualification.

A possible setup confound remains unresolved: the coordinator placed private
experiment state under native configuration ancestry, and the native agent
classified the intended edit target as sensitive. This is a hypothesis about
the setup, not an established cause or product bug. A fresh normally admitted
attempt outside that ancestry was actually running with the same native
permissions and CLI version, a 15-minute envelope and no relaunch. Its outcome
was **unknown at this snapshot**. The first rejected attempt remains a failure.

## A passing prototype still had a real bug

A separate direct Codex fallback produced six private local Python 3.12.10 files
for a synthetic history validator. All **26 author tests passed**. Independent
review still found it **Not Ready**: the 100-digit integer-token limit also
incorrectly rejected long finite float tokens. The test results had missed a
real compatibility defect.

Calibration also found an unsupported legitimate fabricated producer input: a
16 MiB prefix containing 4,000 begins produced artifacts that the provisional
cumulative node capacity refused. An independently justified full rich golden,
complete coherent semantic-mutation and continuity/interruption matrices, and
worst-case calibration remained missing. No real private ledger was used; no
export, site guard, publication or production adoption resulted. This local
prototype is separate from the native product-task attempt.

## What this evidence does not establish

The broader service-owned dispatch and native ingestion work remains unfinished.
The [service shell staging warning](../limitations.html#service-shell-staging)
still applies: a first successful startup adopts a fresh root, after which the
legacy local run/recover/apply paths refuse it until their service clients land.
Authenticated status does not make run.start or attachment.open supported.

Other authoring and review lanes, including this documentation update, used
explicit direct Codex fallbacks after the restricted route refused admission.
They are not MYTHHELM-owned execution. A rejected native attempt is evidence of
self-use and failed delivery, not a demonstrated delivery advantage.

For this November 2 product-task trial, there was no same-contract direct-native
arm, protected paired assignment or closed defect-observation window. No completed full-product baseline establishes
20×, and model labels, overlapping routine records or token counts cannot supply
one. See the [measurement plan](../benchmarks.html). Later outcomes, defects and
charges must be recorded as later evidence, not substituted into this snapshot.
